# Отчет по проекту: Адаптивная платформа обучения с ИИ-репетитором

## 1. Аналитическая часть

### 1.1 Анализ проблемы области

Традиционное образование сталкивается с рядом фундаментальных проблем:

- **Отсутствие персонализации**: В классе из 20-30 человек преподаватель физически не может адаптировать темп и сложность материала под каждого студента. Сильные студенты скучают, слабые отстают.
- **Пассивное усвоение**: Лекционный формат с низкой вовлеченностью приводит к тому, что через неделю после занятия студенты забывают до 80% материала (эффект кривой забывания Эббингауза).
- **Отсутствие системы интервального повторения**: Студенты повторяют материал хаотично, без научно обоснованных интервалов, что снижает эффективность запоминания.
- **Задержка обратной связи**: Преподаватель проверяет работы днями, студент уже забыл контекст. При массовых онлайн-курсах обратная связь вообще отсутствует.
- **Однообразие форматов**: Не учитываются индивидуальные стили обучения (визуальный, аудиальный, кинестетический).

### 1.2 Анализ существующих систем

| Система | Достоинства | Недостатки |
|---------|-------------|------------|
| **Anki** | Интервальное повторение (SM-2), кроссплатформенность | Только карточки, нет курсовой структуры, нет ИИ, устаревший UI |
| **Quizlet** | Простота, игровые режимы | Нет адаптивного алгоритма повторения, нет ИИ-репетитора |
| **Coursera** | Структурированные курсы, сертификаты | Пассивное видео, нет персонализации темпа, нет интервального повторения |
| **Khan Academy** | Бесплатно, адаптивные упражнения | Ограниченно школьная программа, нет ИИ-репетитора с RAG |
| **Duolingo** | Геймификация, адаптивность | Только языки, поверхностный контент |

**Вывод**: На рынке отсутствует комплексное решение, объединяющее:
- Курсовую структуру с темами
- Научный алгоритм интервального повторения (SM-2)
- ИИ-репетитора с доступом к учебным материалам (RAG)
- Ролевую модель (студент/учитель/админ)
- Систему домашних заданий с ИИ-подхватом обратной связи

### 1.3 Анализ инструментальных средств

**Backend:**
- **FastAPI** — асинхронный Python-фреймворк, автогенерация OpenAPI, высокая производительность
- **SQLAlchemy 2.0 + asyncpg** — асинхронный ORM для PostgreSQL
- **Pydantic v2** — валидация данных, сериализация
- **python-jose + bcrypt** — JWT-аутентификация
- **Ollama (llama3.2:3b)** — локальная LLM для ИИ-репетитора (без API-ключей)
- **OpenAI-compatible API** — универсальный интерфейс для эмбеддингов

**Frontend:**
- **React 18 + TypeScript** — типобезопасный компонентный подход
- **Redux Toolkit** — глобальное состояние (subjects, topics, flashcards)
- **Tailwind CSS** — утилитарный CSS, быстрая стилизация
- **Axios** — HTTP-клиент с interceptors для JWT

**Инфраструктура:**
- **PostgreSQL 15** — реляционная БД с JSONB для эмбеддингов
- **Redis 7** — кэш, сессии
- **Docker + Docker Compose** — контейнеризация, единая среда разработки

**Алгоритмы:**
- **SM-2 (SuperMemo-2)** — алгоритм интервального повторения с параметрами: ease factor, interval, repetitions
- **Косинусное сходство** — поиск релевантных фрагментов в RAG
- **RAG (Retrieval-Augmented Generation)** — ИИ отвечает только на основе загруженных материалов

### 1.4 Постановка задачи

**Цель**: Разработать веб-платформу адаптивного обучения с ИИ-репетитором, реализующую:
1. Ролевую модель доступа (студент, учитель, администратор)
2. Систему курсов с темами и карточками для интервального повторения
3. Адаптивный алгоритм SM-2 для планирования повторений
4. ИИ-репетитора с RAG-архитектурой, работающего на локальной модели
5. Систему домашних заданий с чатом обратной связи и ИИ-подхватом
6. Поддержку русского/английского языка и темной темы

**Задачи**:
1. Проектирование БД (пользователи, курсы, темы, карточки, история повторений, задания, чат)
2. Реализация JWT-аутентификации с ролевой моделью
3. Разработка CRUD API для всех сущностей
4. Внедрение алгоритма SM-2 с авторасчетом качества ответа
5. Интеграция Ollama для эмбеддингов и генерации ответов
6. Реализация RAG: chunking, векторный поиск, строгий режим
7. Разработка React-приложения с защищенным роутингом
8. Создание UI чата с визуальной дифференциацией сообщений
9. Локализация (RU/EN) и переключатель темной темы

### 2.2 Модули системы

#### Модуль Аутентификации (Auth)
- Регистрация/вход с JWT
- Ролевая модель: STUDENT, TEACHER, ADMIN
- Middleware для проверки прав доступа

#### Модуль Курсов (Subjects & Topics)
- Иерархия: Курс → Тема → Подтемы (DAG)
- CRUD для курсов и тем
- Дерево тем с визуализацией

#### Модуль Карточек (Flashcards)
- CRUD карточек (вопрос/ответ)
- Привязка к темам
- Отметка "на повторение" по алгоритму SM-2

#### Модуль SM-2 Scheduler
- Расчет интервалов повторения
- Параметры: ease factor, interval, repetitions
- Автооценка качества: correctness × time × confidence × streak
- Пересчет при изменении истории

#### Модуль ИИ-Репетитор (AI Tutor + RAG)
- **Chunking**: разбиение материалов на фрагменты (400 слов, overlap 50)
- **Embeddings**: генерация через Ollama (/v1/embeddings)
- **Поиск**: косинусное сходство в Python
- **Strict Mode**: ИИ отвечает только по загруженным материалам
- **Persona Prompt**: настраиваемый промпт для стиля общения

#### Модуль Домашних Заданий (Homework)
- Создание заданий (teacher)
- Отправка решений (student)
- Статусы: pending → ai_reviewed / reviewed
- Чат обратной связи с тремя типами отправителей

#### Модуль Чата (Chat)
- Сообщения: STUDENT (справа, синие), TEACHER (слева, зеленые), AI_TUTOR (слева, фиолетовые)
- Ручной запрос ИИ-проверки
- Автоматический ИИ-подхват при отсутствии учителя

### 2.3 Ключевые алгоритмы ("изюминки" системы)

#### SM-2 с модификациями
```
quality = correctness × time_factor × confidence × streak_bonus

if quality ≥ 3:
    repetitions += 1
    interval = interval × ease_factor
else:
    repetitions = 0
    interval = 1

ease_factor = ease_factor + (0.1 - (5 - quality) × (0.08 + (5 - quality) × 0.02))
```

#### RAG Pipeline
1. Загрузка материала → chunking → эмбеддинги (Ollama)
2. Хранение в PostgreSQL (JSONB)
3. Запрос пользователя → эмбеддинг запроса
4. Поиск top-k по косинусному сходству
5. Формирование контекста + промпт учителя
6. Генерация ответа через LLM

#### ИИ-Подхват в чате
- Если учитель не отвечает N часов → автозапрос ИИ
- Или студент нажимает "⚡ Спросить ИИ"
- ИИ анализирует submission + правила учителя + пишет фидбек

### 2.4 Инструкция по использованию

**Для студента:**
1. Регистрация/вход (выбор роли Student)
2. Dashboard: выбор курса, просмотр тем
3. Review: нажать "Review →" у темы с карточками
4. Space — перевернуть карточку, 1 — неверно, 2 — верно
5. My Assignments: просмотр заданий, отправка решений
6. В чате: обсуждение с учителем или запрос ИИ-проверки
7. AI Tutor: общий вопрос по материалам курса

**Для учителя:**
1. Регистрация/вход (выбор роли Teacher)
2. Submissions: просмотр работ студентов
3. AI Rules: настройка промпта для ИИ и загрузка материалов
4. В чате: проверка работ и обратная связь
